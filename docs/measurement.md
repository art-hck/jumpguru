# Точность: критерии и протокол исследований

Статус: план валидации, данных ещё нет. Числа ниже — исходные инженерные цели,
не характеристики датчика и не обещание пользователю. Зафиксировать окончательные
критерии до открытия контрольной выборки; не ослаблять их после просмотра результатов.

## Что измеряем

Первая целевая величина — вертикальный подъём общего центра масс от отрыва до вершины
полёта, в метрах внутри ядра и сантиметрах в UI. Это не высота касания рукой,
не перемещение датчика от положения стоя и не расстояние стопы от пола.
Показание датчика на пояснице не тождественно движению общего центра масс.

Для контролируемых прыжков исследуем flight time `h = g*T²/8`, takeoff velocity
`h = v²/(2*g)` и ограниченное интегрирование ускорения. Ни один метод заранее
не объявлен победителем. Flight time предполагает одинаковую высоту центра масс
при отрыве и приземлении; поджатые ноги/иная поза дают систематическую ошибку.
Интегрирование чувствительно к дрейфу, ориентации, фильтрации и начальным условиям.
Результаты [исследования методов на IMU](https://pubmed.ncbi.nlm.nih.gov/30984557/)
мотивируют сравнение методов, но не переносятся как гарантия на WT9011DCL.

Предварительная гипотеза крепления — жёстко фиксированный пояс в области крестца/поясницы.
Висеть свободно, крепиться к одежде или менять место между сессиями нельзя в рамках
одной калибровки. Проверить комфорт/устойчивость крепления; альтернативные места
оцениваются отдельно. Статическая калибровка не доказывает динамическую точность.

## Последовательность

1. **Измерительный тракт:** raw-пакеты, единицы/оси/масштаб, effective sample rate каждого
   канала, timing jitter, gaps, clipping, фильтрация/задержка, длительная screen-off запись.
2. **Пилот:** синхронное видео 120–240 fps (если доступно), несколько сессий,
   прыжки на месте, серии, махи руками; ходьба, бег, приседания и резкие движения без прыжка.
   Видео размечает события/время; само по себе не является точным эталоном подъёма CoM.
3. **Эталон высоты:** предпочтительно силовая платформа с корректным impulse–momentum
   методом для takeoff velocity, либо калиброванный motion capture с моделью CoM.
   Контактный коврик/видео flight time разделяют ограничения flight-time метода.
   Сравнение двух flight-time оценок недостаточно для доказательства истинной высоты.
4. **Набор данных:** предварительно 10–15 участников, не менее двух сессий на человека,
   разные высоты и стили; это пилотный объём, не статистическое обоснование сертификации.
   Добавить независимые игровые записи для баскетбола и волейбола.
5. **Разделение:** по участникам (и их сессиям), а не случайным окнам одного прыжка.
   Train/dev/test manifest фиксируется до настройки, test не используется для порогов.
6. **Сравнение:** один набор входов/разметки для всех методов. Сопоставление событий
   один-к-одному с заранее определённым допуском; сохранять unmatched события обеих сторон.
7. **Контроль:** независимый агент проверяет расчёт метрик, границы сегментов, утечки данных,
   timestamp assumptions, исключения и различие эталонов.

## Измеримые ворота

| Проверка | Предварительная цель / правило |
|---|---|
| Контролируемые прыжки | MAE высоты ≤ 2 см, абсолютный bias ≤ 1 см, P95 абсолютной ошибки ≤ 5 см |
| Обнаружение на контрольной выборке | Precision ≥ 95%, recall ≥ 95%; отдельно по видам активности |
| Пригодность высоты | Не менее 90% размеченных прыжков имеют валидную высоту в заявленных условиях |
| Ложные события | Отдельно false positives на час движений без прыжков, целевой предел фиксируется после пилота до test |
| Повторяемость | Межсессионные bias/LoA и ошибка по участникам, не только общий средний показатель |
| Потери | Каждый наблюдаемый разрыв явно отражён; высота через gap запрещена |
| Длительность | 30 минут screen-off без crash/скрытой потери; затем полный сценарий 90 минут перед MVP |

В отчёте: N участников/сессий/прыжков, MAE/RMSE/bias/P95, Bland–Altman limits of agreement,
интервалы неопределённости с учётом группировки по участникам, precision/recall,
false positives/hour, доля пригодных высот, причины отказов, по каждой активности/условию.
Если данных недостаточно для устойчивой оценки, это явно указать. Отказанные измерения
не исчезают из знаменателя coverage. Прыжок может быть обнаружен, но высота невалидна.

Оценка влияния времени: для `h=g*T²/8`, `δh ≈ g*T*δT/4`. При T≈0.5 с ошибка длительности
10 мс даёт примерно 1.2 см только временной составляющей. Это иллюстрация, не общий
бюджет точности. Время BLE callback нельзя автоматически подставить вместо sensor time.

Если ворота не пройдены, не «полировать» число: менять тракт/метод, ограничивать
подтверждённые сценарии или пересматривать датчик. Контролируемые прыжки и матч —
разные условия. Не переносить успех одного сценария на другой.

## Воспроизводимость и будущая классификация

Хранить manifest с псевдонимами, mounting, firmware/settings, hash сырых файлов,
методом синхронизации/его ошибкой, версией разметки/алгоритма и выбранным split.
Разметку прыжков и категорий проверять независимо; спорное помечать unknown.
Блок/атака/подача сначала размечаются по видео; один поясничный датчик может не давать
достаточно информации для их различения. Решение о ML и дополнительных датчиках —
после проверки этой гипотезы, без ухудшения базовой оценки высоты.
