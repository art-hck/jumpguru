# WT9011DCL: первая аппаратная проверка

Версия плана: 1, 2026-09-20. **Не выполнено:** датчик не подключался, команды не
отправлялись, APK пока отсутствует. Это последовательность для регистратора JG-002,
а не требование владельцу сейчас запускать программы или разбирать логи.

## Подготовка агентом

Агент выдаёт debug APK, инструкцию с названиями кнопок и локальный диагностический
экспорт. Один исполнитель владеет телефонным прогоном. Перед испытаниями нужны:
raw до декодера, подтверждение [профиля/режима](ble-protocol.md), журнал команд/разрывов,
достаточное место и явный индикатор записи. Файлы сохраняются в `local-data/` вне Git;
BLE-адреса/видео/тренировки не публикуются. Внешние приложения использовать по очереди.

Минимальный паспорт прогона (заполняет агент по экспорту и ответам владельца):

```yaml
# Шаблон отчёта, НЕ контракт будущего формата экспорта.
status: not_run
app_sha: unknown
phone: Samsung Galaxy S26+
android_one_ui: unknown
sensor_label_revision: unknown
firmware_display: unknown
firmware_registers_raw: unknown
protocol_profile_version: unknown
output_mode_evidence: unknown
rate_requested_readback_observed: unknown
bandwidth_raw_and_interpretation: unknown
fusion_mode: unknown
calibration_id: unknown
mounting_axes: unknown
battery_before_after: unknown
capture_sha256: unknown
reference_sync_uncertainty: unknown
```

Для каждого шага отчёт содержит pass/fail/not_run, условия, hashes capture,
наблюдаемые показатели и ограничения. Временные окна ниже — план сбора, не заявленная
точность. Ни синтетический декодер, ни ровный BLE график не завершают валидацию высоты.

## Этапы и критерии

| Шаг | Действие владельца после готовности APK | Что проверяет агент / условие перехода |
|---|---|---|
| 1. Экземпляр | Показать маркировку, версии Android/One UI и сведения vendor app | Модель/ревизия, raw версии, фактический GATT; несовпадения разобраны |
| 2. Baseline | Положить датчик неподвижно на стол на 60 с, не менять настройки | Raw сохраняется, режим `55 61` подтверждён; unknown не выдаётся за IMU |
| 3. Оси | По подсказкам положить каждую из шести сторон на 10 с, затем плавно повернуть по трём осям | Знаки, масштаб, норма около g, gyro около нуля в покое; измеренные bias/noise, а не обещанные допуски |
| 4. Калибровка при необходимости | Выполнить отдельный сценарий на горизонтальной поверхности; повторить шаг 3 | Сравнение before/after, новая calibration_id; не скрывать исходный результат |
| 5. Частота/полоса | Записать по 60 с статики и плавного движения для каждого подготовленного режима | 10 baseline, затем 100/200 Гц при подтверждённой поддержке; requested/readback/received отдельно; задержка/повторы/нагрузка |
| 6. Кватернион | Повторить плавные повороты при включённом дополнительном опросе | Конвенция, норма q, age, частота ответов; влияние polling на основной поток |
| 7. Сохранение | Завершить запись, выключить/включить датчик, снова подключить | Readback/фактическая выдача и режим после включения; никаких скрытых reset/calibration |
| 8. Крепление | Надеть пояс, 30 с стоять, затем пройтись, присесть, выполнить несколько комфортных прыжков | Нет болтания; clipping/смещение/магнитные помехи; события пока исследовательские |
| 9. Зал | Пройти площадку, повернуться спиной к телефону; затем 30 минут записи с выключенным экраном | Непрерывность raw, интервалы доставки, разрывы, запись при смене приложений, батарея |
| 10. Разрыв | По сценарию отключить Bluetooth/датчик и восстановить связь | Явный gap/новый epoch, хвост не склеен, режим перепроверен, потерянное не восстановлено |
| 11. Отказы | Только подготовленные агентом сценарии разрешений/остановки процесса/лимита хранилища | Сохранена восстановимая часть raw, сессия interrupted; нет ложного «успешно» |
| 12. Выносливость | После исправлений пройти 90-минутную тренировку | Приёмка MVP по roadmap; результат отдельно от 30-минутного прогона |

Шаги 5–7 со сменой настроек выполняются только после разрешения расхождений
unlock/BANDWIDTH для ревизии. Подтверждать канал/режим нельзя только по похожим числам.
Не моделировать нехватку места заполнением личного телефона: агент готовит ограничение
в тестовом хранилище; реальное поведение ОС проверяет отдельным безопасным сценарием.

Наблюдаемая частота: число полных `55 61` кадров / длительность измерительного окна
по монотонным часам телефона, отдельно от callbacks и `55 71`. В отчёте min/median/P95/max
интервала, длительность пауз, reconnect, malformed frames, queue overflow, write failures,
объём raw и расход батареи. Это метрики доставки, не доказательство sensor ODR.
Проверка временной точности требует независимого эталона; оценка частоты не заменяет её.

## Короткий сценарий для владельца

После получения APK агент даст конкретные кнопки. Физически потребуется:

1. Зарядить датчик, показать маркировку; снять его с зарядки.
2. Положить на стол, запустить запись и выполнить подсказанные повороты.
3. Закрепить на поясе, пройтись и сделать несколько обычных прыжков.
4. Оставить телефон у площадки и проверить запись с погашенным экраном.
5. Остановить запись и передать локальный экспорт согласованным способом.

Если запись/связь остановилась — сообщить об этом, не повторять настройки наугад.
Команды и анализ выполняет агент. Съёмку видео для точности планировать отдельно по
[measurement.md](../measurement.md), включая синхронизацию и определение высоты CoM.

## Проверки реализации до радио

Будущий декодер: signed extremes/LE, точные SI scale, split/coalesced/truncated кадры,
неизвестные flags/регистры, оба режима `55 61`, unknown mode, reconnect mid-frame,
несовпадающий start register, запоздалый ответ и разные возраста каналов.
Будущий регистратор: overflow, отказ записи, interrupted recovery, сериализация команд
и неизменность raw при ошибке декодера. Синтетические fixtures явно маркируются;
реальные capture допускаются в Git только после отдельного разрешения и обезличивания.

## Что остаётся неизвестным

Фактическая ревизия и firmware; поддержка 0x96/readback; действительные unlock и
BANDWIDTH; шкала магнитометра; оси и quaternion conventions; временная связь каналов,
ODR и фильтровая задержка; точные потери; заряд/автономность; связь через тело и
динамическая пригодность крепления. Каждый пункт закрывается evidence, а не датой PDF.
До этого доступна разработка регистратора с raw-only режимом, но не утверждения
о точности высоты или готовности к матчам.
